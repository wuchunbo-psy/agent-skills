# 面试时间协调

## 职责分工

```
用户给：面试官（池） + 候选人 + 可面试时间
AI 做：自然语言 → 脚本参数（无损转译，一次）；按交付契约展示输出（一次）
脚本做：候选人定位 → alias/称谓 → 面试官空闲 ∩ 候选时间 → OR 分配 → 会议室校验 → 完整草稿（措辞唯一事实源）
```

编排是确定性工作，全部在脚本里。**约面任务只有 3 个动作：读本文件 → 跑一条命令 → 照输出交付。**
不 dry-run、不预读源码、不手动拆面试官分头跑——报错才改，改一次。

**跑命令前零查询（查实已内建）**：面试官解析（含缓存）、轮次推导、已约未面剔除都是编排器内建动作，输出里的【缓存命中】【ATS数据匹配】段就是查实结果——不 grep interviewers.json、不翻 _daily_review.json、不调 hire API 预核轮次。**额外实查仅由异常触发**：①候选人当天已面过场或当天新录入（晨间快照可能不含）②用户口径与编排器 ATS 段矛盾 ③编排器报错。三者之外直跑交付；本条优先于记忆/其他规则中任何「接单先实查」类话术。草稿是易腐品——候选人在线等时段，多一轮前置查询就晚一分钟转发。

## 执行步骤

### 1. 确认三要素（缺一问用户，不猜）

| 要素 | 规则 |
|---|---|
| 面试官 | 用户口头给；"A或者B"= OR 池传 `A\|B`，"A和B都要参加"= AND 传 `A,B`；昵称（Sava/Cloud/杰哥等）直接传，按 interviewers.json 的 name/alias/email 前缀解析 |
| 候选人 + 可面时间 | 用户口头给；没给时间的候选人直接写姓名（脚本自动按"明天起 3 个工作日全天"窗口，交付时向用户点明是代拟） |
| 形式 | 默认 `视频`；用户明确说"线下"才传 `--form 线下` |

### 2. 一条命令（编排器，默认入口）

```bash
python "…/schedule-interview/scripts/draft_interviews.py" \
  --interviewer "面试官A" --candidates "候选人V=9-2,候选人W" \
  --interviewer "面试官I|花名C" --candidates "候选人X=9-2 10:00,候选人Y" \
  --lookup-hint "候选人X=主程" --lookup-hint "候选人Y=主程"
```

- `--interviewer` / `--candidates` **成对出现**，可重复=多组；`|` 分隔=OR 池（脚本把每个候选人分给"最早可约"的成员，打平给场次少的）
- 候选人语法同 match_schedule（见第 3 步转译表）；多组候选人可同跑，全部并行查
- **当天新录入的候选人必须传 `--lookup-hint "姓名=岗位关键词"`**（关键词取岗位名稳定片段，如 Unity/服务端/主程；用户没给岗位时从归档路径或 `notes/_hire_result.json` 最近录入记录取）——人才索引缓存隔夜刷新、快照是早晨的，裸姓名当天会 miss
- 编排器内部自动完成：lookup 定位 → alias 为空的面试官按惯例补称谓（英文名直用/中文姓+哥）→ 并行匹配 → OR 分配 → 已约未面的候选人自动剔除并告警（勿重复约）→ 临时文件清理
- 全文落盘 `notes/_drafts_result.txt`（stdout 截断时 Read 它）；开头的分配说明（谁→谁、谁未排上、谁已约未面）交付时要转述给用户

### 3. 转译候选时间（转错=废稿，规则全在此表）

| 场景 | 传参 | 禁止 |
|---|---|---|
| 能确定语境 | 绝对日期 `8-3` | 丢模糊词给脚本猜：今天周一传"周一"会被解析成下周一 |
| 已过时段 | 现在是下午 → 从明天起传；当天临期档脚本按 `--min-lead`（默认120分钟）自动剔除，无需人工判断来不来得及 | 传今天上午（拟安排会落在过去） |
| 候选人说"X点到Y点" | 区间 `8-20 14:00-15:00`（24h制） | 只传起点时刻——语义是"起点以后都行"，会建议出窗外时段 |
| 窗口表达 | 完整传：`8-5\|8-6\|8-7` | 为集中排布压缩窗口——窗口=候选人原话，只有拟安排可优化 |
| 模糊词"这几天都行" | 展开成绝对日期传；**剔除周六日**（调休补班日不算周末，脚本内置当年名单，照常排/画） | 把周末原样传进去——脚本只发 ⚠️ 不拦截 |
| 多日期 | `\|` 分隔（逗号已用于分隔候选人） | — |
| 复杂窗口（"明天上午+工作日下午"） | 同名多条目：`李四=8-5上午,李四=8-6下午\|8-7下午`（编排器自动对齐 talent-id，无需手动重复） | — |
| 精确时刻 | 优先带原话语义词：`8-20 下午4点`（脚本转 24h 制，展示行回显语义词）；纯数字 `8-20 16:00` 也认；**点名午间 12/13 点原样传**（脚本放行午间档） | 候选人明确说要 13 点却自作主张改成 14 点 |
| 同日多时刻（"中午1点和晚上7点都可以"） | 一条传全、保留原话语义词：`赵攀=9-20 中午1点\|晚上7点`（或纯数字 `9-20 13:00\|19:00`）——可面时间行展示全部时刻；拟安排按给出顺序取第一个有空的档，某时刻临期被剔自动轮试下一个 | 只传一个时刻（丢候选人的另一窗口）；单条目内写"或"（脚本不拆条目内的或，必须拆成 `\|`） |
| 宽区间（跨度>2h） | 原样传区间——起点只当边界，档位走黄金时段 | 传起点期望贴起点 |
| 没给时间 | 裸姓名或 `姓名=`（自动默认窗口） | 自己编造窗口传进去 |

### 4. 单组直跑 match_schedule.py（编排器不适用时）

```bash
python "…/schedule-interview/scripts/match_schedule.py" \
  --interviewer 张三 --candidates "李四=8-3,王五=8-4" --talent-ids "<李四tid>,<王五tid>" --form 视频
```

| 参数 | 说明 |
|---|---|
| `--talent-ids` | 与 --candidates 条目顺序对齐；不传则按姓名模糊匹配 ATS（同名歧义时告警）。**部分命中时别传**（空值被过滤会错位对齐） |
| `--form` | 视频（默认）/ 线下；候选人条目可用 `#线下`/`#视频` 单人覆盖 |
| `--duration` | 每场分钟数，默认 45 |
| `--max-per-day` | 默认 0=不限。**AI 不主动传**，仅用户明确要控密度时传 |
| `--days` | 查询窗口天数，默认 7；候选窗口超 7 天必须显式传 |
| `--no-room` | 跳过会议室校验。**无房必须在交付时明说**（无房不卡死、不静默放弃，但要报告） |
| `--work-start` / `--work-end` | 工作时段，默认 9~20（最晚约到 20:00，再晚不排）；黄金时段优先，晚间档只在白天排满时兜底 |
| `--lunch` | 默认 `12-14`（公司午休） |
| `--min-lead` | 当天档位距 now 最小提前量，默认 120 分钟（转发→确认→敲定→手建链时长，临期档视同已过；0=关闭） |
| `--ats-file` | ATS 数据 JSON（默认 `_daily_review.json`；编排器自动产，直跑缺数据时才用 `lookup_candidates.py` 产） |
| `--dry-run` | 只验证解析 + ATS 匹配，不查飞书（调试用；正常约面不需要） |

其他场景：多面试官共同空闲 `--interviewer "张三,李四"`（AND 语义）；单独看某面试官整周档期
`show_availability.py --interviewer 姓名`（日常约面由编排器跑；出档期图用它，见第 5 步）。

### 5. 交付

- **档期图在前、草稿在后（图是默认必交项，不等用户点名）**：每次出约面草稿都跑 `show_availability.py --interviewer X --start <YYYY-MM-DD> --days N --png "<PROJECT_ROOT>/notes/档期图/{面试官名}档期图_vN.png"` 一条命令出图（**日期必须 ISO 格式 `2026-09-04`**，脚本 fromisoformat 不认 `9-4`；`--start`+`--days` 覆盖草稿全部拟安排与备选日期；PNG 3x 是内嵌标准产物，SVG 矢量原稿自动同目录留存；**文件名先查 notes/档期图/ 现有最大 _vN 再递增**（2026-09-28 起档期图统一归 notes/档期图/，存量已迁入）——同路径二次内嵌客户端缓存不刷新；**出图后删除同面试官旧版 png/svg 只留最新**，防过期图堆积）。**脚本产物即交付：不做视觉目检、不派 visual-judge**——图格式为脚本固化契约，重复目检是流程债；仅当图上数据与 freebusy 输出对不上或图明显异常时才看图排查。对话内嵌必须用 markdown **图片语法** `![说明](盘符绝对路径)`——普通链接 `[文字](路径)` 桌面端只显示文字要点开，不用这种
- markdown 色块表**停止交付**：脚本 stdout 里的表格仅供自查数据，不贴进对话；精确到分钟的忙闲段以脚本输出的【忙碌/空闲时间段】为准，图按真实时间轴绘制
- **档期图格式规范（定稿契约，实现在 build_svg；图上数据疑似异常时照此核对排查）**：
  - 布局：一天一行（行头「M/D（周X）」），底部 9:00-20:00 真实分钟时间轴 + 小时刻度；**全空周末整行不画，有会议/面试或是今天的周末日照画（行尾灰「周末」徽标；调休补班日按工作日照画不标）**；已过时段/整日半透明并在行尾标「已过」；右上「当前 HH:MM」胶囊，窗口含当天画当前时刻虚线
  - 色块语义：绿=空闲可约（块内标起止，约 1.5h+ 加「· 时长」，窄块不标防挤）；红=已有会议——**候选人块两行标：上行姓名、下行岗位短名**（短名=投递岗位全名去括号注释、去「开发工程师/工程师/设计师/程序/开发」尾缀、限 7 字；放不下退化为姓名单行居中），**无主会议单行标时刻**；灰=午休
  - 画布宽 = 时间轴区动态计算（viewBox 硬编码旧值会导致右侧裁切、窄块放不下两行标）
  - 图上文案改一处须全 grep：副标题等在 `--svg`/`--png`/`--html` 三个分支独立构造
- 草稿文本放代码块（纯转发文本，复制即发）。多组则逐人（逐图逐稿）
- **候选人链接随草稿一并交付（2026-10-14，排版用户定稿）**：脚本输出末尾 `=== 候选人链接 ===` 段，**每人两行——姓名行 + 纯链接行，链接顶格独占一行**（URL 同 open_interview_dialog.py：`https://mini1.feishu.cn/hire/talent/{talent_id}`；lookup 来源带 `?application_id=` 定位具体投递，快照/`--talent-ids` 直跑为裸链接）。**交付时把这段原样放进代码块**——用户三击整行选中复制即得干净 URL；禁 markdown 链接语法（渲染后复制不出纯 URL）、禁「姓名： URL」同行混排（复制带前缀，发 IM 还降级纯文本）。用户转发面试官时按 AGENTS 飞书铁律单独一条消息发纯链接。链接不塞进可转发草稿文本
- **交付前数人数**：草稿候选人块数 = 应排人数。被挤掉/未排上的人看编排器分配说明或输出【不可约】段，按 ❌ 提示调整
- 拟安排时段冒出新增忙块 → 先核实是否已建场再动（编排器已自动剔除；直跑 match_schedule 需人工核），勿当新冲突重排
- 草稿含 `【需问用户】` → 问用户补齐后手改；用户说改时间 → 重跑命令
- 脚本输出六段（忙碌/空闲/ATS/匹配/草稿+不可约+候选人链接）皆可溯源：忙碌段与飞书日历对不上 = 日程变了，重跑

### 6. 建面试弹窗预开（可选，用户发话才做）

用户敲定时间后让我"打开弹窗"时：

```bash
python "<skill>/scripts/open_interview_dialog.py" 候选人A 候选人B   # --dry-run 只看解析
```

- 脚本解析 talent_id 并每人开一个**独立 Chrome 新窗口**直达人才页；Agent 逐窗口 get_app_state → **元素目标点击「安排面试」** → 确认弹窗出现即报用户就绪。禁用坐标通道和键盘流
- **任何人不得代点「提交」**：提交即向候选人发出正式邀约邮件
- 弹窗默认值直接用：轮次/视频面试(飞书工具)/通知模板；视频面不订会议室

## 草稿格式契约（脚本固化，AI 不改）

```
{称谓}，{团队}——{岗位}，{姓名}推进{轮次}，我和候选人沟通了一下面试时间：

【{今天|明天|无} M/D（周X）】

{姓名}｜{岗位}·{轮次}
　可面时间：{完整窗口}
　拟安排：{M/D（周X）}{今天|明天}{上午|下午|晚上}N点[半|N点MM分]（{视频|线下}）

时间OK的话我直接和候选人敲定～
```

- 称谓 = interviewers.json 的 alias[0]，无 alias 用姓名；编排器自动按惯例补（英文名直用/两字名=末字+哥/三字名及以上=末两字，如王芳→芳哥、王大明→大明；撞存量 alias 回退姓+哥），不让姓名裸奔进称谓
- 轮次由 ATS（interview_count + latest_conclusion）推导：已面 N 轮且上轮通过 → 第 N+1 轮；**interview_count 只数已面完的场**（已约未面不算，编排器直接剔除）
- 候选人块三行各自独立成行；可面时间、拟安排行首缩进一个全角空格
- 多候选人（≥2位）→ 原版逐人三行块 + 唯一增量【日期】组头归堆；单人无组头；任何字段不省略不缩写
- 会议室：有可用 → 草稿完全不提；无可用 → 匹配结果标 ❌

## AI 纪律

**做**：
- 同一面试官面多人 → 一次跑、一条草稿（`--candidates "A=时间,B=时间"`）
- 排布密度：不主动传 `--max-per-day`；场次多时别堆同一面试官，灵活候选人可转 HR 面分流
- 用户一次给的候选人跨面试官 → 多组成对传编排器，一次跑完
- OR 分配结果要转述（谁分给了谁、谁没排上、谁已约未面），用户可指定改排

**不做**：
- 不临场改草稿措辞（不加客套、不加面评、不换格式；用户说调才调）
- 不把候选人原话口语塞进草稿；不堆前序面试官名单
- 不替用户发 IM / 飞书招聘建面试 / 问候选人时间 / 预订会议室
- 不写多维表格（跟踪表已退役，一切以 ATS 为准）
- 不手动拆编排器内部的并行流程（编排器已并行处理）
- 不跑命令前预核编排器内建项（缓存/轮次/已约未面）——零前置查询，异常才实查（见职责分工）
