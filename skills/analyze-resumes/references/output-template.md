# 产出格式模板 v3

> **第一性原则**（2026-09-28 用户定调）：简历初筛是**归纳题不是推断题**——把简历读穿，不往简历外推理。
> 读者的验收线：读完一张候选人卡片（结论头+先问+快读表），**知道他能力行不行、经历含金量如何、产出如何、还缺什么**。
>
> **结构原则**：报告按「**工作室/业务方 → 团队 → 岗位**」三级嵌套组织。业务方拿到报告第一眼能按归属团队拆分发，不需要自己重组。

评估结果输出到 `notes/简历评估/2026-{MM}/简历评估_{M.DD}.md`（按收件月进子目录），同时在终端展示。

HR 的真实阅读动线（报告必须适配这条动线）：
1. **第0秒**：看「本批怎么发」——这报告发不发业务、发谁、谁先打电话？
2. **第1秒**：扫总览——今天整体什么情况？有强推的吗？强推集中在哪个工作室？每个岗的下一步分布？
3. **第1分钟**：翻到自己工作室的岗位章节——扫候选人卡片的结论头+先问+快读表，判断这人值不值得面
4. **第3分钟**：看「同岗怎么选」——业务问"先见谁""有什么区别"时的答案
5. **有空时**：扫 ⚪ 的 Action 清单——这几个我需要做什么才能定？
6. **几乎不看**：🔴（2-3 行理由即可）

## 报告结构（六部分，严格按此顺序）

### 第一部分：总览（第一屏，岗位聚合决策视图）

**一行一个岗位，第一屏直接回答"今天哪些岗有货、先推谁、卡在哪"**。人级明细在第二部分岗位章节里（待定人级跟进在第四部分 Action 清单）。

```markdown
# 简历评估 · {M.DD} · {N}人

> 评估时间窗：{起始时间} ~ {结束时间}。{一句话说明特殊情况：换岗/岗位调整/跨天补归档等}
> 归档根目录（下文所有定位均相对此根）：`<PROJECT_ROOT>/data/在招岗位候选人管理/`

## 总览

> 分工作室分组（▍粗体分隔行），🟡 岗排组内最前；「下一步」说人话不造缩写。

| 岗位 | 档位 | 先见谁 | 下一步 |
|------|------|--------|--------|
| **▍{工作室} · {N}人{M}岗** | | | |
| {岗位名} | 1🟡 | **{姓名}** | **可发业务**（转发语见第 5 部分） |
| {岗位名} | 4⚪ | {姓名} | 电话核 2 · 看作品定 1 · 等补件 1 |
| **▍{工作室} · {N}人{M}岗** | | | |
| {岗位名} | 3⚪1🔴 | {姓名} | 电话核 2 · 定方向 1 · 🔴1 |

**{强推N}** 🟢 · **{可推N}** 🟡 · **{待定N}** ⚪ · **{不推N}** 🔴 · 共 **{N}** 人

**本批怎么发**（按动作分组，做完即闭环——动作当行头，别写成一大段）：

| 动作 | 人数 | 谁与一句话 |
|------|------|-----------|
| 📤 发业务 | {n} | {姓名}（{岗位}{档位}）——转发语见第 5 部分 |
| ☎️ 打电话核 | {n} | {姓名（核什么）}——过线→升🟡补发 |

| 🖼 交业务看作品 | {n} | {姓名}——原件定生死 |
| 📋 等补件 | {n} | {姓名（补什么）} |
| 🧭 先定方向 | {n} | {姓名（方向 A vs B）} |
| 📨 呈批 | {n} | {姓名——呈给谁拍板什么} |
| 📅 已排面 | {n} | {姓名——时间×面试官} |
| 🛑 不推进 | {n} | {姓名——一句原因} |

（只列非零动作行；计数对得上档位统计）
```

### 第二部分：按工作室/业务方分组的详细分析（核心）

**三级嵌套**：`# 工作室` → `## 团队（可选）` → `### 岗位` → `#### 候选人`。

#### 工作室层级（一级标题）

```markdown
---

# 第{n}部分 · {工作室/业务方名称}

{工作室简介，1-2句}本次共评估 {N} 人，{M} 个岗位。{一句关键结论：强推集中在哪/有什么亮点}
```

#### 团队层级（可选二级标题）

**什么时候加团队层**：
- 迷你世界项目团队下有「商业化运营团队」「用户和生态运营团队」——加
- Magnolia 项目团队直接是岗位扁平——不加
- 长青工作室下有「美术端」「技术端」——加（按职能分组也是团队层）

```markdown
## 美术端  // 或 ## 商业化运营团队

{团队简介（可选），通常省略}
```

#### 岗位层级（二级或三级标题，取决于有没有团队层）

**岗位排序规则**：**按强推人数优先**（强推多的岗排前），同强推数按可推数，再按岗位总人数。

```markdown
### {岗位名} — {N}人 · {档位emoji串}

> {特殊说明（可选）：岗位调整/挪岗/历史评估补充等}
```

#### 候选人小节（v4 卡片制，2026-09-29 用户定稿：结论前置+快读表）

> **用户原话驱动**：「前置可推这些信息太模糊，直接把结论前置——处于哪个档位、需要问什么」「能力如何、经历是否匹配、项目含金量，不能快速 get」。四型黑话（前置可推/方向裁决/翻盘窗口/补件）从标题退场，只活在 Action 清单机制里；卡片头部说人话。

**每张卡四层，顺序固定**：

```markdown
#### {姓名} · {岗位}（{团队}）

**{emoji} {行动结论——一句话说清下一步是什么}**｜卡点：{一句话}
**先问**：{1-3 条具体问题，电话/面试直接用}
{→ 过线动作：什么条件满足后走哪一步}

| 快读 | 要点 |
|------|------|
| 能力 | {年限实算+主战场+现职，一句话} |
| 匹配度 | {同类活判定+硬卡核账（学历/年限/base），一句话} |
| 含金量 | {他定的东西被谁在用；写不出就写「只到负责模块清单层」——这是信息不是缺失，一句话} |
| 产出 | {署名/上线/数字/被复用工具；强证据还是弱证据，一句话} |
| 风险 | {异地/空窗/超龄/外包占比/品类跨度，只写客观事实，顿号分隔} |

| 归档 | `{归档根相对完整路径}`（多材料用`；`分隔） |
|------|------|
```

**各档位结论头用语（去黑话，emoji 保留当视觉锚）**：
- 🟢 `**🟢 可直接发业务**` + 强推三道关一行（①同类活 ②实质责任 ③敢用，各 ✓/✗+短语）
- 🟡 `**🟡 值得约面**`（有悬念时加「｜面询定成色」）
- ⚪ `**⚪ {前置动作}后{可约面/可定/重评}**`——如「电话过线即可约面」「先定方向再评」「等补件」「看作品原件定生死」「呈批件（大概率收）」
- 🔴 `**🔴 不推**`——无先问、无快读表，原因 1-2 行+归档即收

**写法纪律**：
1. **结论头是卡片的第一行**——HR 不展开任何表格，扫结论头就该知道：这人什么档、卡在哪、第一个电话/面试问什么。
2. **先问必须在最前**（用户要求）；问题要能直接转发面试官、答完能定档。
3. **快读表每格一句话**（硬上限两行），塞不下的是没消化，不是篇幅不够。
4. 归型判断（谁卡前置、谁看作品）保留在「过线动作」里表达，不出现四型名词。
5. 一事实一主位置：核账细节（每段经历）不进卡片——那是 _eval_9.28/*.md 明细的职责。
6. **信息页要跨附件找，别停在「简历」命名的那个（2026-09-29 高梓晋两次教训）**：简历 PDF 文本层是水印/图片型时**先渲染目读**；第一个附件没有信息页 ≠ 没有——**逐个附件翻**（信息页常藏在「作品集」PDF 第 1 页，用户实测纠正过）；全部翻完仍无才落「等补件」，归因写「各附件渲染目检均无信息页」。
7. 术语纪律延续：不出现 v2 的「决策卡/钩子/雷/标尺对照」。

---

**小节硬规则**：

1. **档位必须与三支柱自洽**：同类活✗ 却给🟢 = 结论矛盾，强制降档。⚪ 的卡点与过线动作必须在结论头说清（黑话四型退场，动作说话）。
2. **核账不省**：年龄（>32 标 ⚠️超龄）、base 轨迹（全轨迹无广东标 ⚠️异地）、学历达标判定、年限核账（虚标≥0.5 年标出）、空窗月数（≥6 标 ⚠️）、**外包占比**、**品类跨度**——这些客观项任何一项简历里没有 → 写「未知」+ 落补件，禁止留空、禁止静默省略。
3. **效力边界**：🟢🟡 的「先问」行即效力边界，必写且必具体。⚪🔴 的「先问」写核验/看件动作本身（信息缺口态）。
4. ⛔ **归档可见性三规则**：①文档头**声明一次共同归档根目录**，此后全部定位=`{批次}_{N}份/{档次}/{文件名}`，不再整段重复长路径；②批次/档次放**小节标题**，文件名放**归档**cell——**长路径禁止进表格 cell**（撑爆列宽，飞书渲染尤其差）；③自检标准——**HR 不点开任何小节，光看总览和小节标题就能说出每人在哪天、哪个文件夹、哪个档次**。兜底区/已评收录备查的人同样标位置，漏人一眼可见；执行噪音路径（`_extract_`/`_tmp_`）永不出现——`_eval_{M.DD}/{姓名}_评估.md` 是唯一的合法明细引用（它是评估档案不是执行噪音）。
   - ⛔ **cell 标签必须写「归档」二字，不可写「文件」（2026-09-17 周洁分发漏件事故）**：`finalize_report.parse_report()` 的归档行判据写死 `if "归档" in line and "`" in line and line.strip().startswith("|")`——**含「归档」二字的表格行才会被收集为待分发路径**。写成「文件」→ 该人文件**不会被 mv 进档位子目录**（若该人此前已分发过，脚本会走"探测各档位子目录"兜底分支而侥幸跳过，让错误被掩盖，新增候选人则直接漏发）。**🔴 极简版和 ⚪ 极简版也必须保留这一行归档表格**（哪怕全卡只有这一行），砍掉它=分发漏件。
   - ⛔ **cell 内的路径必须是「归档根相对完整路径」，不能只写文件名**：脚本用 `os.path.join(ARCHIVE_ROOT, rel)` 拼绝对路径，只给文件名会拼出不存在的路径 → 报"未找到/无法定位 N 件"。**多人同批次时，每人路径都要带全前缀**。
   - ⛔ **多材料用 `；` 分隔，路径本身不要夹中文括号说明**：`（+`_作品集.pdf` 74页）` 这种写法会让正则把 `_作品集.pdf` 也当成一条路径（无前缀 → 报 missing）。正确写法：`` `…/张三_岗位_3年.pdf`；`…/张三_岗位_3年_作品集.pdf` ``。

**档位 emoji 串**：岗位名后加 · 跟档位 emoji，如 `— 2人 · 🟢🟢` 或 `— 3人 · 🟢⚪🔴`。

#### 同岗怎么选（v3 新增，取代排序决策表）

**2 人以上时必写**。回答业务必问的两句："先见谁""有什么区别"。

```markdown
> **{岗位} · 同岗 {N} 人怎么选**：先见 **{A}**——{一句话理由，指向可指认的事实}。
>
> {A} 与 {B} 的决定性差别：{A 能指认"我定的东西被谁用"；B 只有参与署名}——**面试验**：{这句差别对应的具体问法}。
```

**纪律**：
- **不排序表、不排名次**——名次在素质相近时是假的（2026-09-28 用户：排序表"其实没啥用"）。
- **区分点必须可指认且可验证**：写"A比B经验丰富"= 空话；写"A 能报出规模数字、B 只写'参与'"= 可用。
- **每条区分点必须配一句面试验法**——否则区分点只是纸面判断，业务无法当场验证。

**v3 改版理由**（回测实证）：当年周广🟢排#1、欧灿龙🟡排#2，实际两人都被张杰一面否。真区分点是"周广按执行方式重复13年 vs 欧灿龙品类不折算"——**排序表装不下这种判断**，它只会说"周广>欧灿龙（13年主程+多款上线）"，而这恰好是错的。

### 第三部分：推荐摘要（每人一句转发语，复制即发）

**独立章节，格式统一，复制即发。** 不带薪资、不带隐私（电话邮箱不出现）。

**每人一行**（不是完整段落——🟢🟡 小节已有全量分析，这里重写一遍是复写反模式；业务群转发场景要的就是一句话）：

```markdown
---

# 第{n}部分 · 推荐摘要（可直接转发业务）

> 本章节为复制即发版，不含薪资/电话/邮箱等隐私。按工作室分组，每人一句。

## {工作室1} · {岗位}

- **{姓名}**：{一句钩子：年限+最强同类活事实}；{一句风险（面试确认点），无雷省略}。

## {工作室2}
...
```

**写法**：钩子句直接复用该人小节「**能力与经历**」的核心事实（可微调措辞适配业务视角），不重新组织长段。业务被一句话勾住了 → 回报告看该人小节。
> 注：这里的「钩子」指**转发语的吸引力**，是本节专有词，与 v2 已废除的"决策卡/钩子行"无关。

```markdown
---

# 第{n}部分 · 需人工看原文件

- **{姓名}**：{issue}（图片型 PDF/扫描件/乱码/空文本），BOSS 标 {年限} {岗位}。

## 判定 emoji

| 档位 | emoji | 含义 |
|------|-------|------|
| 强推 | 🟢 | 同类活✓+责任轨迹有实质责任实证+无未清前置，优先推给业务 |
| 可推 | 🟡 | 同类活✓，但轨迹证据薄或有一处须面询才能定的缺口——值得安排面试 |
| 待定 | ⚪ | 信息缺口（前置未清/方向待裁/缺件），解决后进流程 |
| 不推 | 🔴 | 同类活✗（方向不对口）或硬门槛不达标 |
| 已评估 | — | 历史已评估过，本次不重复评 |

## 岗位排序规则（重要）

**岗位在工作室/团队下的排序，按强推人数优先**：

1. 强推人数多 → 少
2. 同强推数，按可推人数多 → 少
3. 同可推数，按岗位总人数多 → 少
4. 全相同时，按岗位名字母/拼音顺序

**为什么**：让最有价值的岗位排在前面，HR 扫到第一眼就是强推最多的岗位。避免"3 🟢 的岗被排在 1 ⚪ 的岗后面"的反直觉情况。

**示例**（长青美术端）：
```
- 游戏地编（1🟢） → 3D动作（1🟢） → 3D场景（1🟢） → 3D角色（2🟡，无强推） → 游戏UI（1⚪）
```

## 特殊情况处理

### 换岗（候选人投错岗位后改投）
- 文件挪到正确岗位目录
- 在正确岗位章节正常评估
- 总览表的「一句话理由」里标注"（换岗修正）"
- 在岗位小节开头用 `>` blockquote 说明换岗情况

### 岗位调整（评估后用户判断更合适别的岗位）
- 文件挪到新岗位目录
- manifest 同步更新 target_dir/filename/path/job_name
- **新岗位章节**正常评估
- **原岗位章节**保留但只剩其他候选人
- 总览表「一句话理由」标注"（岗位调整）"
- 总览后单独 blockquote 说明调整原因

### 已评估候选人补发材料（作品集/补充简历）
- 文件归档到原有岗位目录（不要重复创建 7.XX_N份）
- 在岗位小节加一行简短说明，不重复评估

```

**不直接判死，落待定⚪方向裁决**。按评估要点"外部信号和简历事实打架 → 标存疑"。

## 单岗位专项报告变体（跨批次整合/岗位专诊时用）

一个岗位积了多批人、或用户点名"把这 N 个人整合成一份"时，产出**单岗位专项报告**，与日报的差异：

1. **总览退化为人员行表**（岗位聚合视图在单岗位下没有信息量）：`| 姓名 | 判定 | 年龄/年限 | 批次/档次 | 一句话理由 |`，全岗位恒定字段（工作室/团队/岗位名）写进文档头一句话，不占列。
2. **统一横向比较跨批次拉通**（分批各排各的=没比较），节末「同岗怎么选」必加。
3. **文档头声明一次共同归档根目录**，正文全部用短路径定位（归档可见性三规则）。
4. 可加「看作品优先级」段（美术类岗位专用）：按"先看谁、在哪个批次文件夹"列取件顺序。
5. 溯源段列出被整合的历史报告链接，声明档位与事实一致。

## 反模式（产出格式专属）

- **不要扁平岗位列表** — 必须按工作室/团队分组，HR 要按业务方拆分发。
- **不要总览表缺「先见谁」/「下一步分布」**、总览后缺「本批怎么发」 — 岗位聚合决策视图的第一屏价值就在这三处。
- **不要结论不前置** — 卡片第一行必须是「档位 emoji+行动结论｜卡点」，第二块是「先问」；HR 不展开任何表格就要能拿到这三样。
- **不要快读表格子超过两行** — 每格一句话，塞不下说明没消化，不是篇幅不够。
- **不要🔴进快读表** — 🔴 = 结论头+1-2 行原因+归档，一个 🔴 的行数超过一个 🟢 的卡片 = 结构倒挂。
- **不要用四型黑话进标题** — 「前置可推/方向裁决/翻盘窗口/补件」只在机制层（Action 清单/评估明细），卡片头部说人话。
- **不要🟡 只写"待确认"** — 必须配一句能直接转发给面试官的具体问题。
- **不要猜简历判不了的东西** — 认知深度/抗压/动机/产品敏感度只能以问题形式出现（v3 最高纪律）。
- **不要排序表排虚名次** — 用「同岗怎么选」：先见谁 + 决定性差别 + 面试验法。
- **不要同岗多人无对比** — 业务一定问"先见谁""有什么区别"。
- **不要待定判据模糊** — "建议复核"是废话，必须写"差什么信息、看什么就能定"，且 ⚪ 必归四型之一。
- **不要把 Action 清单的「工作室/团队」列漏掉** — HR 要按业务方拆任务跟进。
- **不要同一事实多处复写** — "判断行+标尺依据+证据段+排序表+摘要五处换措辞重复"是旧版最大的乱源：一事实一主位置，其余短语引用。
- **不要素材淹没判断** — 「能力与经历/含金量/产出」三段必须在小节最顶部；🔴 超过 3 行 = 结构倒挂。
- **不要砍掉归档表格行** — 任何档位的极简版都必须保留「归档」cell 行（finalize 分发依赖）。
