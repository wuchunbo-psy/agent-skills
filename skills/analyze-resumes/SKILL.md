# 简历评估

`collect-resumes` 的下游：对当天新归档的简历逐份做 AI 筛选评估。

## 配置

| 项 | 值 |
|---|---|
| 归档根目录 | `<PROJECT_ROOT>/data/在招岗位候选人管理` |
| 评估结果输出 | `notes/简历评估/2026-{MM}/` 按月子目录（写 `简历评估_{M.DD}.md`；MM=收件月，如 2026-09） |
| 评估要点文件 | 各岗位文件夹根的 `评估要点.md`（和 JD 同目录） |

归档目录结构、命名、档位子目录见 `collect-resumes/references/archive-contract.md`（单一真相源）。

## 最高优先级约束：行动加速原则 + 不猜纪律（v3）

**报告的每一部分都必须服务于 HR 的一个具体行动决策。读者看完任何一个章节，都知道"下一步做什么"。**

**核心成败约束（2026-09-28 用户定调）**：简历初筛是**归纳题不是推断题**——不猜他脑子里有什么（不可判），只回答"他的过去，支不支持让他来聊一次"。**把简历读穿，不往简历外推理。**

核心验收线（三层递进）：
1. **第 0 秒**：总览下「本批怎么发」直接回答"发不发业务、发谁、谁先打电话"；
2. **每人 30 秒**：扫卡片结论头（档位 emoji+行动结论｜卡点）+「先问」两行，知道**他什么档、卡在哪、第一个电话问什么**；再看快读表五行拿到能力/匹配度/含金量/产出/风险；
3. HR 不打开原简历就知道这人的位置与断点，**卡片「先问」那 1-2 句可以直接转发给面试官**。

> **v3 三支柱**（完整规则在 analyze-prompt.md）：① **同类活判定**（他做过的和这岗要做的是一类活吗）② **责任轨迹**（同一段经历里他承担的东西涨没涨；实质责任>名义责任）③ **产出可指认**（留下了什么别人能验证的东西）。
> **横向修三条**：跨品类降档 / 外包驻场降档 / 名义责任无实质支撑则🟢封顶。


## 执行流程（5 阶段）

### 阶段1：提取文本（一条命令）

```bash
python "…/analyze-resumes/scripts/collect_and_extract.py" \
  --date 8.05 --output-dir notes/_extract_8.05
# 跨天批次多 --date 一次跑（OCR/渲染模型只加载一次）
```

- 目录不存在（无新简历）→ 告知用户，结束。
- ⚠️ **这里有两个不同的「日期轴」，别混（2026-09-17 蔡文勇案例，曾误判报告该落哪天）**：
  | 轴 | 由什么决定 | 用在哪 |
  |---|---|---|
  | **归档日** | 归档日规则推算（①19 点后收到算次日 ②周六/日收到算下周一），见 `collect-resumes/references/archive-contract.md` | **归档目录名**（`9.18_1份/`）与 `collect_and_extract.py --date`（它按目录前缀扫描） |
  | **收件日** | `received_at`（邮件真实收到时间） | **报告名单口径**——`notes/简历评估/2026-{MM}/简历评估_{M.DD}.md` 的日期段与 `finalize_report.py --date` 的 `reconcile` |
  - 两者**在 19 点边界会分叉**：19:03 收到的简历 → 归档到**次日**目录 `9.18_1份/`，但**归入收件日**报告 `简历评估_9.17.md`。
  - 所以遇到这类件：**提取用归档日**（`--date 9.18`，否则扫不到该目录）、**报告与收尾用收件日**（`--date 9.17`）。报告里如常写全该件的归档相对路径即可，两个日期各司其职。
  - `finalize_report.py` 的对账按 `received_at` 匹配 → 19 点后收到的件在收件日报告里**不会被列为差异**（它本就在收件日名单内）。
- 清点：脚本输出的发现人数与归档人数对账，少了逐个排查（zip 内简历/含简历的打包件是已知漏提取类型）。
- 清单里 `🖼️BOSS加密(已渲染图片)` 的人：主会话先探测本会话视觉能力（读 1 张图试），有 → 视觉读 render_pages 后写回 JSON 的 text 字段（重跑提取自动复用，不重复渲染）。渲染图已按 **2 页/张拼合**（`combined_N.png`）：先读第 1 张（含基本信息+近段经历），履历核账/经历细节需要时再读后续张。无视觉能力 → 归兜底区，不逐页尝试。
- 清单里 `⚪图片型` 的人：主会话/子智能体有视觉 → 渲染前 3 页直接目读背景信息写回 JSON text（读简历不是看作品），不再一律兜底；`🎨纯作品集`（zip 内无任何简历件）→ 兜底区（无背景可评，交业务看原件）。
- 批量读 JSON 前先合并落盘 UTF-8 文件再 Read（提取文本含 PDF 控制字符，直接 stdout 会判二进制/乱码；合并前正则清 `[\x00-\x08\x0b\x0c\x0e-\x1f]`）。
- 单份排版错乱需挽救：`extract_text.py <file> --recovery`；单独渲染：`extract_text.py <file> --render-pages <dir>`。
- 加密 PDF 想要 OCR 底稿（无视觉能力时的降级）：`ocr_render_pages.py <extract_dir>`。

### 阶段2：取评估要点

每个有简历的岗位，**先 Read 该岗 `config.json`，再读 `评估要点.md`**（两步都做，缺一不可）：

**① `config.json`（2026-09-28 新增，必做）** — 取三样：
- `base`：**岗位工作城市，异地判定的唯一依据**（候选人 base 轨迹对照此值，全轨迹无该城市 → 标 ⚠️异地）。缺失 → 在摘要里报告"岗位 base 未标，异地未判"，**不要猜**。
- `同名岗区别`：同名异岗的口径差异（若有）。**项目里有要求相反的同名岗**——长青「3D动作设计师」要 3D 动作，坤灵「资深3D动作」2026-09-23 起要 2D 骨骼为主。**套错口径会把完全对口的人误判成方向倒挂**（2026-09-28 实测误杀一次）。
- `job_code`：录 ATS 时用。

**② `评估要点.md`** — **v3 下只取两样**：**同类活的定义**（这岗要的活是什么）+ **两个关键取舍**（这岗宁要什么、不要什么）。要点里的「教学块」「搭桥」节是最有价值的资产，直接复用。
- ⚠️ **不再逐条打 ✓/△/✗ 标尺表**（v3 废除）。旧版要点的"判定标尺"只当同类活定义读。
- 要点缺失 → 读 JD 按 v3 结构起草（**同类活定义 / 两个关键取舍 / 硬门槛 / 雷区**，四节即可），输出给用户，**阻塞等确认**后落盘。起草一次性，落盘后只读不覆盖。
- **存量兼容**：旧版要点（v1 六段散文 / v2 判定标尺）照读不误，只是不打分。**要点迁移只改活跃岗**（用户 2026-09-28 拍板）：在旧要点上**新增一节**「同类活定义 + 关键取舍」，旧结构保留不动。

**base 城市速查**（2026-09-28 ATS 全量查实，各岗 config 已写入）：坤灵项目团队 / 长青工作室 / 迷你世界项目团队 / Magnolia·产品团队 = **深圳**；山海工作室 = **广州**。


### 阶段3：逐份分析（子智能体并行评，主会话汇总）

评估由定义式子智能体 **resume-judge** 执行（定义在 `~/.zcode/agents/resume-judge.md`）——**但 v3 切换期必须按下面的优先级派**：

**⚠️ 派单优先级（2026-09-28 实测教训）**：
1. **先派 `resume-judge`，并在 dispatch 消息里显式要求它"第一件事 Read 两个判据文件"**（路径见下）。实测：`resume-judge` 的正文改动**在新会话里生效**；但同日改完立即派，可能仍走旧版缓存。
2. **收到返回后做一次 v3 冒烟检查**：返回内容里若出现"标尺 ✓x △x ✗x""决策卡""钩子/雷"这类 **v2 词汇** → **说明它跑的是旧框架，本次产出作废**，改派 `general-purpose` 并把 v3 判据要点直接写进 dispatch 消息（见下方模板），重跑该人。
3. **稳妥做法（推荐大批次用）**：直接派 `general-purpose`，dispatch 消息里写全「先 Read 这两个文件 → 按 v3 三支柱评估 → 产出格式要求」，不依赖 agent 定义的加载时机。

**dispatch 消息必备要素**（缺哪项它会 blocked）：候选人姓名 / 简历绝对路径（正斜杠）/ 岗位名 + 岗位目录绝对路径 / **岗位类型** / 输出目录 / 备注（无则写「无」）。并明确要求它 Read：
- `references/analyze-prompt.md`（v3 权威判据，**含 §-1 开工前置与 §0.1 分析边界**）
- `references/output-template.md` 的「候选人小节」节
- **该岗 `config.json`**（取 `base` 与 `同名岗区别`）
- 详细输入契约见 `resume-judge.md` 的「四、输入」

**备注可靠性纪律（2026-09-30 加，9-29 两起 dispatch 备注与简历原文冲突）**：备注里的年限/空窗/经历断言必须来自**已读全文**的提取文本；只看过文本头部摘要时不要写年限核账类断言（judge 会纠错但浪费一轮对账）——核账本来就是 judge 的职责，dispatch 备注只写「渠道信号/业务动态/已知拍板」等 judge 从简历里看不到的事实。

- **作品一律不看（2026-09-17 用户定稿）**：作品集图片/zip 内散图/视频都不看不渲染，无论美术岗与否。美术类候选人**直接评简历文本背景**（年限/经历/项目/声称的作品产出），不再先派 portfolio-eye 目检——两跳管线已废除。作品原件统一进报告第 5 部分「需业务看原件」清单。
- **简历信息页 ≠ 作品**：图片型简历（含 BOSS 导出 jpg）为拿背景事实可以渲染读——这是读简历，不是看作品；主会话有视觉就直接看，不绕 OCR。**简历作品一体 PDF 只读前 3 页（硬上限 5 页），从第一张纯作品页起即停**，不往后翻。
- **portfolio-eye 已退役备用**：仅用户点名争议件/终验时手动派，常规流程不进管线。
- **主会话保留**：对账防漏人、**同岗怎么选**（替代原排序决策表）、报告组装（output-template 六部分）、对外发送。小批次（≤4 人纯文本简历）主会话可直接做，不必派。

判据文件（analyze-prompt / industry-knowledge）由子智能体每次开工自读；主会话组装报告前必读 output-template（凭记忆写报告 = 格式漂移）。


**作品未验的表达纪律**：美术候选人的作品相关描述按简历声称写，并在卡片「先问」注明「作品未验，需业务看原件」，**不因看不到作品而一律降档或落待定**——档位基于简历背景事实。历史目检翻盘案例见 `references/decisions.md`。

### 阶段4：产出报告

必读 `references/output-template.md`（六部分结构 + 候选人小节**v4 卡片制**〔结论头=档位行动结论｜卡点 → 先问 → 过线动作 → 快读表五行〕+ 「同岗怎么选」段 + 「本批怎么发」段），写入 `notes/简历评估/2026-{MM}/简历评估_{M.DD}.md`（按收件月进子目录）并在终端展示（总览表+本批怎么发必发）。

**组装自检必跑（2026-09-30 加，9-29 两起组装事故后固化）**：报告落盘后、finalize 之前跑
`python "…/scripts/report_lint.py" <报告路径>`——机械校验四项：标题人数=卡片数、卡片岗位=所在章节岗位（防并行子卡贴错章节）、章节人数标注=实际卡片数、每章节有「归档位置」行+每卡有归档行。exit 1 先修复再发，不许跳过。

- ⛔ **一天一批，只写一个文件（2026-09-17 晚班教训）**：`finalize_report.py` 固定读 `notes/简历评估/2026-{MM}/简历评估_{M.DD}.md`，**没有"晚班/第二批"概念**。同一天傍晚又来简历时，**并入同一份报告、人数累计**，**不要新建 `简历评估_9.17晚班.md`** —— 拆两份会让档位分发口径错乱且脚本读不到。
- **合并/改写报告时守住三个字段**（否则档位分发静默漏件，见 output-template 小节硬规则 4 的三条 ⛔）：① 归档 cell 标签必须是「**归档**」（不是「文件」）；② 路径必须是**归档根相对完整路径**（不是裸文件名）；③ 多材料用 `；` 分隔、路径旁不夹括号说明。


### 阶段5：收尾一条链（必做，评估完自动进，不等用户问）

```bash
python "…/analyze-resumes/scripts/finalize_report.py" --date 8.05
```

自动完成：manifest 对账 → 简历按档位 mv（强推/可推/待定/不推 四档分开，2026-09-30 定；历史批次兼容识别共置目录 待定·不推）→ 份数校验（verify_archive）→ 派生飞书发布版 → drive import → IM 发链接给吴春波。

- 对账有差异 → 脚本 exit 1 并列差异；确认合法（已评估收录/跨天补归档/历史积压）后加 `--force` 重跑。
- import/发送失败 → 脚本自动发本地路径兜底消息；手动发布路径见 `references/publish-lark-doc.md`。
- `--dry-run` 预览分发计划；`--skip-publish` 只分发+校验+生成发布版。

完成后告诉用户：飞书文档链接 + 本地 md 路径 + 各档人数。

## 判断纪律（完整规则在 analyze-prompt.md，此处只列总纲）

1. **不猜（最高纪律）**：简历层判不了的（认知深度/抗压/动机/诚实度/产品敏感度）绝不给确定性描述，只能以**具体问题**形式出现在卡片「先问」行。降档只能用可指认的事实（外包署名/品类跨度/轨迹断点）。
2. 🔴不推是重判：理由里每个事实必须能在简历原文指出；外部信号（BOSS 届数/经验）与简历事实冲突 → 标"存疑"落待定。
3. 拿不准就落⚪待定，不硬给档位；⚪ 的 Action 必须可执行（差什么信息、看什么就能定）且必归四型之一（前置可推/方向裁决/翻盘窗口/补件）。
4. **🟡 必配具体问题**：写"待确认"= 不合格。问题要能直接转发给面试官、答完能定档。
5. 同岗位 2 人以上必做**「同岗怎么选」**（先见谁 + 相邻两人的决定性差别 + 面试验法），**不排虚名次**。
6. **实质责任 > 名义责任**：出现"覆盖N类场景/熟练使用N种工具"列举式描述 → 消费者信号，降档（周广案）。
7. 不碰薪资（BOSS 收简历时已按薪酬期望筛过；用户 2026-09-28 再确认：薪酬不是初筛该操心的事）。
8. 不看作品：视频、作品集图片、zip 内散图一律不看不抽帧，报告写「作品未验证，需业务看原件」+ 归档路径，不因此落待定。
9. 美术岗只评简历文本背景（2026-09-17 用户定稿，废除必目检）；简历信息页（含图片型）可渲染读——读简历不是看作品。
10. **一事实一主位置**：同一事实只在一处展开，其余短语引用。
11. **卡片制（v4）**：结论头前置（档位行动结论说人话，四型黑话不进标题）；先问紧跟结论头；快读表每格一句话（硬上限两行）；🔴 不进快读表。

## 反模式（执行层）

- **不自写提取/收尾脚本** — 阶段1 用 `collect_and_extract.py`，阶段5 用 `finalize_report.py`，全链已覆盖。`extract_text.py` 只用于单份 `--recovery` / 单独渲染。
- **不打标尺表** — v3 已废 ✓/△/✗ 逐条打分（资格项过了就不该再占版面，是"看起来客观"的伪信息）。
- **不进卡片黑话/长文** — 结论头说人话；快读表格子超两行=没消化，返工信号。
- **不评估完不收尾** — 阶段5 必做：报告躺在 notes/ 不算完成，档位文件夹 + 飞书文档到达 HR 屏幕才算闭环。
- **不跳过必读 reference** — 判据三件套（analyze-prompt / industry-knowledge / 评估要点）由子智能体每次开工自读；主会话组装报告前必读 output-template。凭记忆写报告 = 格式漂移。
- **不对同人重复计名** — 脚本已按 姓名+岗位 去重；报告名单与归档人数不一致时先查再发。
