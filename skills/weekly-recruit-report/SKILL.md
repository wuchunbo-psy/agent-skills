# 每周招聘周报

## 这个 skill 解决什么

周报不是流水账，是**向上沟通 + 资源整合的途径**。三种典型失效模式：

1. **只写过程不写结果**——"持续跟进""继续推进"，看不出干成了什么；
2. **卡点藏着不说**——卡点是给别人介入的接口，不说等于放弃资源；
3. **计划没有动作和数字**——"加强寻访"无法验收，下周没法销账。

本 skill 把周报收敛为**四问框架**，并固化数据口径，让每个数字可复现。

---

## 周报四问框架（核心）

| 问 | 写什么 | 硬要求 | 反模式 |
|---|---|---|---|
| ① 这周做了什么 | **结果**：数字 + 完成态 + 名单 | 每个数字与 ATS 核对；上周计划逐条销账（兑现/延期+原因） | "持续推进了XX工作" |
| ② 发现什么问题 | **卡点**：卡在哪、影响、需要什么资源 | 卡点显性化分级列出；写"需要什么"，不只写"有问题" | 美化、省略、埋在段落里 |
| ③ 为什么会出现 | **归因**：卡点的根因 | 归到可改变层面（标准/渠道/方法/外部），不归到"忙""没注意" | 只写现象等对方追问 |
| ④ 下周怎么调整 | **可执行计划**：动作 + 目标数字 + 时限 | 每条可验收（SMART）；与②的卡点一一对应 | "加强/持续/继续做好" |

框架的推导依据见 [`references/decisions.md`](references/decisions.md)。

## 工作流

```
① 定周窗口        周一 00:00 ~ 周五 23:59（本地时区）
    ↓
② 拉 ATS 数据     interviews（周窗口）/ applications（update 时间过滤）/
    ↓             offers / 入职（stage 变更）——契约见 ../lark-hire
③ 核口径          按「数据口径铁律」过滤+拆解（全系统 → 本人线）
    ↓
④ 拉过程记录      本周每日 todolist + mentor 沟通原文（结果要与计划/指示对上）
    ↓
⑤ 销账上周计划    上周周报的"下周计划"逐条回写：兑现 ✓ / 延期+原因 / 取消+原因
    ↓
⑥ 按四问组织      完成事项（①）/ 个人总结（②③合并写）/ 下周计划（④）
    ↓
⑦ 产出           md 详实版（底稿）+ docx 提交版（结构随团队惯例）
```

---

## 数据口径铁律

1. **ATS 是唯一事实源。** 周报里所有数字（场次/人数/入职/Offer）必须系统核对，不用体感数字。
2. **个人排期 = interviews 按 creator=本人过滤。** interviews 接口返回全系统（含其他 HR），不过滤会把别人的量算进来。
3. **"场"类计量必须拆解表述。** 标准写法：「排期 N 场（实际执行 M 场，X 人，初试 A 场）」：
   - 同人各轮各算一场（一人走 3 轮 = 3 场），须同时给按人×岗位去重的人数；
   - 改期在系统留两条排期（原场 + 新场），实际执行数要扣除未进行的那条；
   - 数字被质疑时：先出**逐日逐场清单**核对，再修表述——不先改数字。
4. **按岗位归属过滤。** applications/interviews 用本人岗位快照（`_my_jobs.json`，会过期，岗位增减后刷新）过滤；他人岗位上的代建排期单独标注归属，不混入个人产出。
5. **offers 按岗位线归属过滤**，非本人线不写。
6. **入职时间**以沟通确认为准：系统 stage 的 enter_time 是操作时间（常为提前一晚批量操作），不是实际到岗日。
7. **applications 按 update 时间过滤会带出全系统记录**——先过滤本人岗位，再做任何统计。

## 输出模板

```
<title>招聘周报（M.D–M.D）姓名</title>

一、本周完成事项            ← 问①，2~4 块，每块：结果+数字+名单
  1. [Offer/入职线]         入职 N 人（名单+日期）、Offer 发出/接受、待入职队列
  2. [面试推进线]           场次（口径拆解写法）+ 分布 + 关键候选人走到的轮次
  3. [运营/标准线]          流程机制、标准调整、卡点标记
  4. [AI+招聘线]            工具落地进展（有结果才写）

二、个人总结                ← 问②③，卡点如实+归因+工作方式复盘
  本周主线一句话 → 卡点分条（现象/归因/需要什么）→ 方法或方式的调整

三、下周计划                ← 问④，每条：动作+目标数字+时限
  1. …（谁/什么事/做到什么程度/什么时候前）
  …
  末条固定：上周未闭环事项的补救动作（如有）

四、下周招聘优先级          ← 优先级/项目/岗位 三列表格，随本周实际调整
```

---

## 输出前自检

1. 每个数字都能在 ATS 复现（知道它从哪个过滤口径来）
2. 上周计划每条已销账（兑现/延期+原因）
3. 卡点都有"需要什么"，不只"有问题"
4. 下周计划每条有动作+数字+时限，无"加强/持续/继续"类空条目
5. 场次表述含 执行数/人数 拆解
6. 候选人归属、事项时间与本周沟通记录交叉核对无矛盾
7. 工作方式类反馈（如有）在个人总结有回应，且有对应动作

---

## 反模式

- ❌ 用体感数字或口径不清的数字（"面了三十多场"）
- ❌ 同人多轮不注明，数字虚高引来质疑
- ❌ 把全系统数据当个人产出
- ❌ 卡点美化或省略——周报是沟通途径，藏着=放弃资源
- ❌ 归因归到"忙/没注意"（不可改变），应归到标准/渠道/方法（可调整）
- ❌ 计划不可验收，下周无法销账
