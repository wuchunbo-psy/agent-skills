# 归档命名规则

> 目录结构、文件命名、档位子目录、计数规则的**单一真相源**是 `archive-contract.md`。本文件只补充 archive-contract 未覆盖的【同人打包规则】。

## 同人打包（简历 + 作品）——2026-09-22 从美术端扩到全岗

- 候选人自己发的现成 zip → **不能直接用原包归档**：必须先解压查包内简历，脱敏包内简历薪酬（PyMuPDF redact），重新打包后再归档（zip 等价替代，7z 不能建 RAR）。原因：verify_archive 用 os.walk 进不去 zip，扫不到包内简历的薪酬，原包归档=薪酬泄漏。
- 候选人发的 zip 命名不规范（含电话、原始前缀等）→ 重新命名后归档
- 简历和作品分开发 → 打包前可在日期文件夹内建临时子文件夹暂存，打包完成后删除子文件夹
- 打包后命名：`{姓名}_{岗位简称}_{经验}年_简历加作品.zip`
- **闸门强制（2026-09-03 加，2026-09-22 扩全路径+关键词判定）**：verify_archive 对**任何岗位**的目标目录检测同姓名下简历类与作品类散件并存，命中即 STOP「同人散件未打包」——归档 resolve 时就当场打包，别等闸门拦。判定口径：
  - 文件名含「作品/portfolio」→ 作品类（**PDF 作品集也算**，修复按扩展名把作品集.pdf 当简历的盲区）；文件名含「简历/resume」→ 简历类（含图片简历）；无词按扩展名兜底（pdf/docx/doc=简历类，图片/压缩包=作品类）
  - **合集命名豁免**：文件名含「简历加作品/简历作品/作品简历」= 打包终态，不参与散件判定（单文件合集 PDF 合规，不必强打成 zip）
  - **视频必须打包（2026-09-23 用户拍板，废除旧「视频独立保留不进包」豁免）**：mp4/mov/avi 等视频作品每人打成一个 `{姓名}_作品视频.zip`，与简历放同一档位子夹——散放每次都要再整理、容易混乱。视频不打进简历加作品.zip（视频压不动，简历包保持即取即用）；散视频会被闸门 STOP「视频散件未打包」；`{姓名}_作品视频.zip` = 打包终态，不参与散件判定；zip 内成员不是散件
- **跨批次同人提示（2026-09-22 加，warning 不阻断）**：同岗位同人材料出现在 ≥2 个批次目录 → ⚠️ 提示 Agent 判断是否吸收合并（补交材料归当天批次是合法流程，重投/双下载产生的新批次是否并入由 Agent 按材料内容判断，不强制 STOP）
- **整合存量的一人一包原则（2026-09-22 用户拍板）**：已有 zip 解开重打、绝不套娃；同 SHA 副本只收一份；包名诚实——包内无简历类材料的包名用「_作品集.zip」不用「_简历加作品.zip」

## 只有简历、作品已含在 PDF 中

和普通岗一样，按 archive-contract.md 的文件命名规则。
